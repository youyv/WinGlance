# 最终方案实施与验证

日期：2026-11-28（UTC+08:00）。开发基线：`605b7fd488c2df781e9243db33b14e678b37a7d3`。
依据本机 `artifacts/antigravity-plan-conclusions.md` 的最终实施方案，顺序为 A/B 修复、C 测量、D 功能。

## A/B 修复

- 连接详情先切换数据归属，再判断是否能查询。暂停、断线、切换应用、进程身份变化和已经排入 UI 队列的旧结果都受归属/查询代际校验；同一应用保留明确标记观察时间的历史端点，相同结果不重新绑定列表。
- 采集器把连接代际、有效帧接收、统计入队和实时快照提交纳入同一短临界区。聚合准备和外部事件通知在锁外；旧连接回调失效。使用单调时钟判断 6 秒停滞，重复序列不保活；睡眠恢复等待新帧。概览、统计、托盘与悬浮条共用状态模型。
- 端点先按每个已验证进程保留数值顺序 Top 200，再复核进程存活，最后选全局 Top 200。最多 512 个进程、单个原生表 8 MiB、四张表顺序读取。16 MiB 是查询显式拥有的活动缓冲预算，不是整个 App 内存上限。显示截断、身份失败、表不可用、进程上限和预算不足分别报告。
- 启动项的严格命令解析与当前安装路径匹配分开；移动目录仍能识别已保存的静默偏好。初始主窗可见性决策之后才创建悬浮条；托盘或穿透失败恢复交互，保留保存的穿透偏好。故障后普通设置保存不重新启用穿透。

## C 测量方法

`scripts/measure-diagnostics.ps1` 使用冻结发布包和 100 个应用的确定性 1 Hz 回放。其中应用 000 持有真实 40 个 UDP 端点，连接详情走原生 IP Helper 查询；其余应用用于可重复的列表更新/重排。
场景为概览、Acrylic、穿透、连接详情、托盘加穿透、禁用图表、禁用列表位移动画。正式每场景 5 轮交错、预热 10 秒后测量 60 秒，分别报告 App 和回放进程的 CPU；回放进程不能作为真实 Collector 的开销结论。

每轮重新建立独立空数据库作为一致模板，记录窗口可见性、前台状态、DPI、尺寸、系统环境、发布文件哈希及资源端点。真实采集器和 Flush 的 EventPipe 诊断单独运行，不混入未启用 trace 的 CPU 对照。CPU 按逻辑处理器数归一化，汇总同时保留原始轮次、中位数和 IQR。

用户现有应用保持运行，因此后台业务负载不是完全隔离的实验条件。短轮只验证脚本和初筛，不能替代正式多轮结果；历史 333 MiB 工作集及旧 CPU 记录不作为本轮通过依据。

### 端点算法压力测量

原始结果：`artifacts/endpoint-benchmark.json`，5 个用例各 5 轮交错运行，共 25 轮。

候选结构实际为 56 字节；512 个进程各保留 200 个候选并持有 8 MiB 原生表缓冲时，显式活动存储高水位为 14,565,376 字节（约 13.89 MiB），低于 16 MiB 预算。

| 512 × 201 条 TCP6 | 正向 | 15.542 ms | 5,921,988 B |
| 512 × 201 条 TCP6 | 反向 | 9.728 ms | 5,921,988 B |

### 悬浮条生命周期补修

以每个 App 实例一个 WinUI 悬浮窗替代每次切换重新创建窗口。关闭按钮/Alt+F4/菜单只隐藏，真正退出才释放；隐藏期间停止位置计时器和绘制，原生穿透 HWND 同样复用。修正独立事件退订与 Acrylic 控制器的 finally 清理边界。此为应用侧生命周期规避，不宣称已定位 Windows App SDK 原生分配堆栈。

隔离 v4 的 25 次开关类型对照：总句柄 1372 → 1394，静置 60 秒回到 1349；Composition 16 → 21 → 16，WaitCompletionPacket 60 → 61 → 60，Timer 50 → 44 → 41。GDI 恒 60，USER 61 → 61 → 55。另行 UIA 只查找不切换的对照没有持续增长。这一短轮解释了原三类句柄的修复效果，但不能替代长轮验证。

随后的 v4 两模式各 100 次复核暴露残余：Acrylic 内核句柄 1321 → 1444，静置 60 秒仍 1428；穿透 1320 → 1339 → 1337，没有相同单调斜率。再用独立 Acrylic 长轮逐类定位，Event 在 0/25/50/75/100 次分别为 532/571/596/618/636，静置 60 秒仍 634，而 Composition 与 WaitCompletionPacket 恒定。发现此新证据后暂停 D 实施，继续处理。

## D1：统计导出

统计页增加 CSV / JSON 手动导出，点击时固定范围、应用筛选和排序。统计单写者实际执行时只读取一次时钟，绕过旧缓存、跳过趋势查询，产生脱离可变聚合对象的只读导出数据；后台格式化和文件写入不占用统计队列。整机汇总不受应用筛选影响，应用网络 / 磁盘占比分母为筛选前的全部可归属应用总量。

两种格式保留机器单位、未知值、有效秒数、覆盖率、峰值时刻及 ETW 质量。CSV 为 UTF-8 BOM、单一标准表头，对可疑外部文本添加可见前缀并报告数量，数字列仍为数字。默认不包含路径 / 命令行 / 图标路径。

保存对话框使用独立 STA 的 IFileSaveDialog，仅选择路径；写入使用目标同目录独占临时文件。取消与提交共用状态锁，提交开始后不接受取消。覆盖失败区分已知普通失败和部分替换状态；不能确认时保留恢复文件并显示路径，不先删除原目标。退出只等待不依赖 UI 的后台 writer，必要的失败 / 恢复位置写入统计错误日志。

独立保存对话框 8 项实机通过：新目标未被提前创建、已有目标在选择覆盖后字节不变、用户取消、已取消 / 极早取消 / 可见时取消、拒绝覆盖后取消、覆盖确认期间取消。普通 Close 在本机部分场景返回成功却未结束模态循环，因此补充对同 STA / 同 PID、由 IOleWindow 得到的确切对话框发送正常关闭消息。该处理不枚举并关闭其他窗口，也不声称可强制中断挂起的 Shell 扩展。原始结果：`artifacts/save-dialog-verification-v3/report.json`。

集成版 `artifacts/feature-integration-v1` 的导出 UI 10 项通过：实际 JSON / CSV 文件、1 个过滤应用与 100 个应用的分母口径、常规刷新和导航保留结果、UTF-8 BOM、用户取消、撤销会话结束保持对话框、确认会话结束取消对话框且无 UI 死锁。结果：`artifacts/smoke-20261128-222806/export-verification.json`，正常清理，无强制结束。

前两次导出 UI 自动化因对话框层级和重复 AutomationId 选择错误而超时；保存对话框实际已打开。脚本改为在所属主窗口下定位，并核对保存按钮名称，随后通过。这些失败日志保留，不将其记为产品通过。会话结束使用定向消息注入，不等于真实注销 / 关机。

## D2 / D3：连接筛选、复制与悬浮条预设

连接详情新增协议与状态筛选，仅作用于本次已取得的最多 200 条端点，保留独立的来源数量、截断 / 权限提示和观测时刻。右键可复制本地端点、远端端点或 TSV 整行，UDP 无远端时禁用该项；点击捕获的行不会因随后刷新转移到另一进程。实机发现文本默认菜单会拦截右键，现统一由整行处理自定义复制。
