# C 阶段 UI 与端点测量

2026-11-28，测量包为 `artifacts/repair-baseline-v2`。35 轮 UI CPU 测量和两组 100 次悬浮条开关均完成，包文件与电源计划前后未变，所有隔离实例正常退出。悬浮条开关暴露出持续的内核句柄增长，后续诊断与修复必须单独记录；本报告不把这份冻结包描述为无泄漏，也不代表后续功能版本的性能。

## 环境与复现

- Windows NT 10.0.26300.0；Intel Core i5-8400，6 核/6 逻辑处理器，约 16 GiB 物理内存。
- 深色主题，96 DPI，主窗口 1400 × 900 物理像素；电源计划 GUID `381b4222-f694-41f0-9685-ff5bb260df2e`。
- 固定 100 个合成应用，每秒一帧。应用 000 的连接详情使用诊断采集器实际持有的 40 个 UDP 回环端点。每轮独立空 SQLite 和独立设置，不读取用户历史数据。
- 用户正在运行的 WinGlance、增强采集器及 Firefox 直播保持不变。后台活动会带来测量波动；这不是专用静止测试机。
- 每场景 5 轮，顺序按轮次轮换；预热 10 秒、单调时钟计量至少 60 秒。CPU 以整机 6 个逻辑处理器归一化。前台窗口保持置顶，托盘场景核实主窗口不可见，采样结束后才恢复检查数据新鲜度。
- 测量时没有构建、EventPipe 或其他诊断实验并行。每秒记录资源和可见性，并以 PID、启动时间及完整可执行文件路径验证控制对象。用户既有进程明确排除。

## B1 高端点数合成基准

`scripts/tools/endpoint-benchmark` 链接产品实际候选池、原生表解码、预算与最终端点格式化代码。五次预热后，以轮换顺序执行五轮；大表每轮 10 次，退出场景每轮 200 次。完整原值位于 `artifacts/endpoint-benchmark.json`。

| 输入 | 每次 wall time 中位数 ms | Q1 / Q3 ms | 当前线程托管分配中位数 B |
|---|---:|---:|---:|
| 512 进程 × 201 TCP6，正序 | 15.54157 | 15.24295 / 15.58271 | 5,921,988 |
| 512 进程 × 201 TCP6，逆序 | 9.72814 | 9.69251 / 10.00147 | 5,921,988 |
| 512 进程 × 1000 UDP4，正序 | 23.66620 | 23.21425 / 26.97713 | 5,886,788 |
| 512 进程 × 1000 UDP4，逆序 | 67.71637 | 67.56379 / 68.21188 | 5,887,131 |
| A 的 240 条已退出，B 的 10 条存活 | 0.035133 | 0.035098 / 0.042907 | 82,464 |

计时包含有界身份规格化、注入原生表复制/解码、各进程 Top200、给定存活集合筛选、全局 Top200、最终字符串及所拥有 HGlobal 的申请/释放；不包含操作系统表枚举、进程句柄身份/存活检查或构造输入。因此这些数值不能称为真实整机 IP Helper 查询耗时。逆序 UDP 会增加堆替换工作，保留其较慢结果。

候选结构实测 56 B。最大 8 MiB 原生表与 512 个完整候选堆同时存活时，显式拥有的工作存储高水位为 **14,565,376 B**，低于 **16,777,216 B** 预算；该计数包含 384 KiB 元数据/输出预留，释放后仅保留该预算预留数值。它不是 App 总内存上限，也不是累计托管分配上限。
